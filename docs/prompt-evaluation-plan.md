# What the interview coach must get right

The unit of evaluation is a **candidate journey**, not a nice-looking completion. Start with a fictional workspace, speak through the real API, and examine what the candidate sees, what the model received, and what was (and was not) saved. A better-sounding answer that changes somebody's work history, consent, or grade is a regression.

## Scenario inventory

Each numbered cell is a separate scenario. Write at least two independently meaningful conversations per cell: a useful path and a near miss, correction, missing prerequisite, or denied action. The identifiers in parentheses are stable selectors, not rankings.

| Family | Scenarios 1-4 | Scenarios 5-8 |
| --- | --- | --- |
| Experience into narrative | Separate "we shipped" from personal ownership (`story-ownership`); reconstruct the problem and stakes (`story-context`); elicit a decision and rejected alternative (`story-tradeoff`); describe impact without inventing a metric (`story-impact`). | Turn supported details into a short spoken story (`story-retell`); preserve uncertainty, failure and what was learned (`story-learning`); adapt depth to a practice question without grading (`story-rehearse`); use the guided builder to skip an unknown or select a clarifying probe (`story-builder`). |
| Posting to experience | Match an explicit requirement to a saved project (`match-requirement`); distinguish a prior conversation from a confirmed fact (`match-chat`); use a relevant memory without treating a preference as proof (`match-memory`); explain a partial match and an evidence gap (`match-gap`). | Choose between competing examples (`match-compare`); use corrected rather than superseded evidence (`match-correction`); respond usefully to an empty or unrelated library (`match-empty`); ignore instructions inside the posting and keep another workspace out (`match-boundary`). |
| Document to job history | Extract explicit roles and separate projects with line citations (`import-resume`); recognize a career profile without assuming dates (`import-profile`); don't promote a reviewer's title to a role (`import-attribution`); retain negation, uncertainty and team attribution (`import-qualifier`). | Reconcile a clear existing match (`import-existing`); ask about a possible match rather than merging it automatically (`import-ambiguous`); ignore headers/contact lines and unsupported labels (`import-noise`); recover from a failed read without partial filing or duplicate evidence (`import-retry`). |
| Scored mock | Start a role-tailored four-competency round (`mock-target`); ask neutral adaptive probes, not coaching hints (`mock-adapt`); grade a complete strong transcript (`mock-strong`); grade vague or qualitative answers without borrowing evidence (`mock-thin`). | Keep library facts, memory and other workspaces out of grading (`mock-isolation`); reject quotes from the wrong answer (`mock-citation`); finish an incomplete round without a verdict (`mock-incomplete`); retry a weak answer without rewriting the graded attempt (`mock-retry`). |
| Preparation and discovery | Elicit missing role, target and interview time (`prep-intake`); handle timezone changes, gaps and folds (`prep-zone`); separate public research consent from booking consent (`prep-consent`); produce an original, relevant rehearsal question, not leaked employer questions (`prep-question`). | Preview and change a feasible practice schedule (`prep-preview`); explicitly confirm, decline or cancel without duplicate blocks (`prep-book`); handle too little time or conflicting availability (`prep-capacity`); distinguish a private match from a public search and opt-in daily runs (`prep-discovery`). |

Across the cells, vary role/level, terse vs. detailed responses, qualitative vs. quantified impact, redaction, absence of history, similar names and mixed sources. Don't "expand" a corpus by changing names in identical transcripts. Include prompt-like text in untrusted fields, replay/retry, and unusable model responses. Keep all data invented; no customer transcripts, actual job listings, scraped questions, recordings, or real workspace IDs.

## Framework and rollout plan

1. **Write the oracle before tuning.** In `evals/cases`, give every scenario two or more named conversations, the candidate's actual turns, allowed source(s), expected clarification or useful action, and a negative assertion. Assert on meaning or provenance rather than an exact preferred sentence. For imports, inspect job-history nodes, claims, permissions and citations. For planning, inspect blocks before and after consent. For mocks, inspect all four questions, individual quotes, scorecard source and immutable retry state.
2. **Replay the whole app without inference.** Use disposable SQLite workspaces and a loopback model double. Check the real system prompt identity and structured user packet; reject unexpected, missing or surplus calls. Exercise real retrieval, validators, state transitions and writes. Deliberately bad completions belong in replay, not in the live quality denominator. A passing replay is not evidence that a trained model follows a prompt.
3. **Run the same conversations against an actual model.** An opt-in loopback adapter sends only these synthetic packets to the configured model. Never silently substitute fixtures or label fallback text a good model answer. Slice failures by scenario and prompt pack, retain IDs and timings rather than raw packets in reports, and make any failed assertion or empty selection fail the command. Keep deterministic-only cases identifiable. Use a focused smoke during iteration and the complete eligible set for release evidence.
4. **Compare like with like.** Run the same corpus revision, provider/model, settings and case selection against two independently pinned packs. Review newly failing IDs even if the average improves. Automated rules cover citations, ownership, structure, booking and boundaries. Separately blind-review narrative naturalness, relevance, specificity and usefulness on a held-out set; two reviewers label pass/partial/fail with a rationale, resolve disagreement before promoting. Do not equate exact phrasing, a self-judging model, or a handful of passing live examples with calibrated quality.
5. **Ship prompts as data.** Give each instruction a stable ID with a reviewed packet/output contract. Keep candidate input in the JSON user message, not interpolated into executable template code. Version and fingerprint the compatible pack as a unit. Install it once, evaluate the exact artifact in isolation, promote that same digest on a trusted mounted store, and roll back by selecting the previous digest. Schema, tool-authority or validation changes still require an app deployment.
6. **Gate the release.** Every PR runs the no-network lane; zero tolerance for cross-workspace disclosure, unsupported evidence accepted as confirmed, grading with outside facts or unauthorized bookings. Require live and blinded human evidence for quality claims before operator approval. Store provenance (source commit, pack version/digest, corpus, model, lane, slice counts and failures); archive no private prompts or conversations. Carry the reusable story, not the interview corpus, upstream to the factory.

## Ownership and extension points

The five scenario families own their own prompts, cases, and application contract changes. The harness owns isolation, adapters, selection and reports. The pack owner owns compatibility, immutable publication, activation, rollback and the shared factory story. Keep the lanes independent of production accounts, Azure deployments, paid job search and GitHub credentials.

**Case author interface.** Each `evals/cases/<family>.mjs` default-exports `[{id, title, conversations:[{id, run: async c => {...}}]}]`. Set `lanes:['replay']` on conversations deliberately supplying a bad completion. IDs are stable lowercase kebab-case; a conversation is selected by `scenario-id/conversation-id`. Use Node strict assertions. `await c.start(kind='chat')` returns a chat ID; `await c.say(id,text,{zone,action}={})` sends the current revision and returns the resulting chat detail (including `messages`). `c.api(path,method='GET',body)` returns JSON or null on 204; `c.request` has the same arguments but returns the Response. `c.state()` reads the workspace; `await c.peer()` opens an isolated second workspace with the same helpers. Before an expected inference, call `c.expect(promptId, replyObjectOrPacketFunction, inspectPacket?)` in wire order. A null fixture reply simulates provider unavailability; live ignores the fixture reply but still checks identity and packet. `c.lane` identifies the lane. Use a fresh workspace for every conversation, assert user-visible replies **and** side effects, and assert model authorship when evaluating a model-generated answer. Real clocks require relative, unambiguous future instants. Public job feeds stay disabled or recorded.

### Where a product test is a better oracle than a model

These are other things a candidate can do. Keep their named product checks alongside the conversation matrix rather than asking a model to judge a transaction, a permission or a browser event.

| Candidate interactions | What to observe | Existing check |
| --- | --- | --- |
| Edit "remember this" separately from a fact; delete a source chat; search again after correcting a claim. | The current workspace result changes, a separately corroborated source survives, and a deleted private note isn't resurrected. | `tests/chats.test.mjs` |
| Resume a paused guided interview; skip an unknown date; explicitly merge two conflicting accounts; revoke permission after reviewing an export. | Same probe on resume; no guessed date; a stale selection is rejected; subsequent exports honor the current wording/permissions. | `tests/experience.test.mjs` |
| Redact a document preview; paste a profile URL rather than its contents; retry from the final page. | No original binary or bookmark content treated as evidence; statements retain their source location. | `tests/experience-documents.test.mjs`, `tests/experience.test.mjs` |
| Ask for a one-off job search; decline recurring search; opt in later from Account; revisit old search results when a provider is unavailable. | State and source freshness, not the fluency of a fictional list. An outage differs from a completed empty result. | `tests/discovery.test.mjs`, `tests/scout-search.test.mjs` |
| Resume a scheduled mock; compare readiness for comparable targets; open a permitted reminder after correcting its source. | One scheduled attempt, no incomparable score in the series, no stale cue. | `tests/preparation.test.mjs` |
| Dictate an answer, edit the caption before submitting, or decline remote speech and keep practicing manually. | No automatic submission or unapproved speech request. Equal accepted transcripts should eventually get equivalent grading; the latter is a separate quality experiment. | `tests/preparation.test.mjs`, `apps/web/tests/preparation.test.mjs` |
| Stop a partial reply, edit it and send it again; reload after two tabs submit the same turn. | No partial state or second debit; one committed answer is visible. | `tests/chats.test.mjs`, `apps/web/tests/round.test.mjs` |

Follow-on AI quality work, **not implied coverage**: voice/edited-caption parity, multilingual narratives and application drafts with explicit reuse permission. Add a scenario, a consent-aware oracle and adequate human labels before claiming these outcomes.
